## The problem

Compilers apply optimization passes — Constant Folding, Dead Code
Elimination, and the like — to make generated code smaller and faster. In
practice, they're almost always run in one fixed, hand-picked order. But
passes interact: running Constant Propagation *before* Constant Folding
exposes more foldable expressions than running Folding alone. There is no
single fixed order that's optimal for every program. This is a genuinely
open problem in compiler research, known as the **phase-ordering problem**.

## The approach

Instead of committing to one fixed order, I treated phase ordering as a
search problem. A chromosome is a sequence of six optimization-pass names;
a population of 30 random sequences evolves over 40 generations using
tournament selection, single-point crossover, mutation, and elitism —
searching for the sequence that produces the smallest, cheapest code for
the *specific* program being compiled.

The safety-critical piece: before trusting any sequence's score, the
optimized program is actually executed by a small interpreter and its
output is compared against the original program's output. A sequence that
changes what the program computes scores exactly zero, regardless of how
much smaller the code got. This is what makes it safe for the search to
explore aggressively.

## Architecture

```
source code → Lexer → Parser → AST → IR Generator → Three-Address Code
                                                            │
                              ┌─────────────────────────────┴──────────────────────────────┐
                              ▼                                                              ▼
                  Traditional fixed-order optimizer                                Genetic Algorithm
                  (one hand-picked pass sequence)                     (searches 6-gene pass-order chromosomes)
                              │                                                              │
                              └──────────────────────────────┬───────────────────────────────┘
                                                               ▼
                                                  Correctness-checked comparison
```

Every optimization pass — Constant Folding, Constant Propagation, Copy
Propagation, Common Subexpression Elimination, Dead Code Elimination,
Strength Reduction — is a small, independent, unit-tested function
operating on the same Three-Address Code representation, which is what
makes them freely composable and reorderable by the genetic algorithm.

## Results

On the flagship example, the traditional single-pass-each order gets from
12 instructions down to 6. The genetic algorithm discovers that running
Constant Propagation a **second time**, after folding, propagates
now-constant values directly into the program's output statements — after
which Dead Code Elimination removes everything else, collapsing the
program to 3 instructions. That's a concrete, reproducible demonstration
of the phase-ordering problem, and of evolutionary search solving it
better than a fixed order.
